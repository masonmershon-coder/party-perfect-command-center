# How we choose applicants

Source of truth for Mike (scoring + chat): `lib/hiring-selection-playbook.ts`.  
Reject learnings: every delete asks why → stored in Redis → Mike uses patterns next time.

## Always hiring

**All positions stay open:** tents, delivery, linen, dish, warehouse, showroom, sales, open.  
Urgency still varies by season (tents/delivery often hottest), but never auto-reject great people for “wrong department this week.”

## Path we often use for labor crew

**Tents first → if they stick → ride-alongs / delivery.**  
Showroom/sales hire into their lane when the fit is right.

## Score bands

| Score | Action |
|------:|--------|
| 85–100 | Strong hire-ready — flag Josh, same-day text |
| 70–84 | Solid call today — flag |
| 55–69 | Review in Hiring |
| 40–54 | Weak / incomplete |
| 0–39 | Gates / mismatch — don’t flag |

## When you reject/delete

Pick a reason (required). Mike learns:
- not physical / outdoor  
- schedule  
- reliability  
- commute  
- experience  
- wanted different role  
- hired someone stronger  
- duplicate / withdrew / other + notes  

## Same-day call questions (crew)

1. Lift tables / tent gear in heat?  
2. Weekdays + weekend peaks? Start date?  
3. Valid license (delivery path)?  
4. Confirm outdoor physical — not only phones
